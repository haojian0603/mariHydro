# T06 测试、文档与门禁收口

负责人建议：最熟悉测试体系、CI 门禁、文档对齐的人

## 1. 目标

把前 5 个任务的架构意图固化为：

- 可运行测试
- 文档事实
- 架构审计规则
- 提交门禁

## 2. 边界文件

主要范围：

- `crates/mh_physics/tests/*`
- `tests/*`
- `docs/*`
- `scripts/architecture_audit.ps1`
- 可能涉及 workspace 顶层脚本与 CI 配置

## 3. 必须解决的问题

### 3.1 测试门禁

- 把关键物理回归纳入稳定门禁：
  - 守恒
  - C-property
  - 干湿转换
  - Thacker
  - 溃坝
  - 关键线性代数/并行一致性

- 明确哪些慢测试保留 `ignore`
- 明确哪些必须进入 nightly / full suite

### 3.2 文档对齐

- 更新分层文档，避免继续引用失效 crate 路径
- 更新模块说明，去掉“已迁移/待迁移”与现实不符的表述
- 对主路径与实验路径给出明确标记

### 3.3 架构扫描门禁

- 将 `architecture_audit.ps1` 从“候选问题生成器”升级为“门禁规则的一部分”
- 最少纳入以下规则：
  - 生产代码 `unimplemented!` 禁止
  - 主路径 `CpuBackend<f64>` 专属实现禁增
  - `legacy`/`deprecated compat` 禁增
  - `mh_agent` 主路径裸 `f64` 快照禁增

## 4. 拆解步骤

1. 盘点现有测试，按“快速门禁 / 慢回归 / 基准测试”分类。
2. 与 T02/T03/T04/T05 对齐需要新增的回归测试。
3. 修正文档与注释，使其与代码现实一致。
4. 升级审计脚本规则并输出新的审计报告格式。
5. 形成最终 DoD 检查表。

## 5. 非目标

- 不负责改公共接口
- 不负责改业务算法本身
- 不负责做临时兼容层

## 6. 验收标准

- 有一份明确的门禁矩阵。
- 关键测试不再只停留在文档层面。
- 审计脚本规则能对重构成果形成约束。
- 文档不再引用失效 crate 与失真分层。

## 7. 预期冲突点

- 会与所有任务的最终导出和测试名称发生调用点冲突

处理方式：

- 本任务不抢接口定义
- 所有冲突通过最终收口统一调整
